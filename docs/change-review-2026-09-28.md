## 发现与修复

| 优先级 | 触发条件与影响 | 修复 |
| --- | --- | --- |
| 高 | 第一份自动保存尚未返回时继续输入；旧响应会覆盖新草稿，同一字段的并发请求还可能使较旧内容最后写入数据库。 | 自动保存字段保留尚未确认的本地修改；同一字段的写入依次执行，关闭编辑器时提交最后一次修改。普通选择状态仍按外部值更新。 |
| 高 | 单镜头重写返回不完整 JSON，或写入尾帧时失败；接口可能返回成功，或留下只更新了一部分的镜头。 | 完整校验六个文本字段；镜头、首帧和尾帧在同一个数据库事务内更新，任一步失败即回滚。 |
| 中 | 刚修改提示词、机位或时长就点击生成；失焦保存尚未完成，生成已经读取旧内容。保存失败时也仍可能继续生成。 | 页面汇总各字段的待保存操作，单镜头生成、批量生成和提示词生成先等待保存成功；剧本生成也采用相同的保存顺序。 |
| 中 | 切换分镜版本时先改变版本标识，再加载镜头；返回分镜页时又默认选择最新版本，已有镜头却可能来自旧版本。 | 剧集接口同时返回实际加载的 `versionId` 和镜头。页面直接使用该版本标识，切换前完成保存，加载过程中禁用生成入口。预览合成使用实际加载的版本。 |
| 中 | 视频提示词声明了角色参考图，却只发送场景图；首尾帧模式误用参考图模板；模型空返回、重复镜头结果或缺少场景图时仍可能继续。 | 参考图模式按声明的顺序发送角色图和场景图，提示词生成与视频生成使用相同的剧集角色集合和顺序；首尾帧模式使用首尾帧描述。空提示词、重复结果和缺图请求被拒绝，已有提示词保持不变。 |
| 中 | 批量重新生成失败后点击重试，覆盖设置丢失；旧素材可能被直接跳过，却显示重试成功。 | 重试保留原请求的覆盖设置；只在原分镜版本展示和执行该次失败重试。 |

保存协调只负责当前编辑页面的字段，不引入后台任务系统。仍使用 `use-debounce` 管理延迟，使用 Zod 校验模型结果，使用 Drizzle 事务保证成组写入。没有增加旧接口包装或旧数据格式的运行时兼容分支。

## 回归验证

本地验证结果：13 个测试文件、57 项测试全部通过，比上一轮增加 15 项回归用例；ESLint 零错误零警告，TypeScript 检查和生产构建通过，全量依赖审计未报告已知漏洞。

新增 React Testing Library 和 jsdom 作为开发依赖，用真实 React hook 行为验证自动保存，不在生产代码中模拟组件生命周期。

- 自动保存：延迟响应期间继续输入、同一字段连续写入、编辑器卸载时提交、生成等待保存、保存失败后阻止生成。
- 批量重试：保留重新生成时的覆盖设置；切换版本后不执行旧版本重试，返回原版本后可重试失败项。
- 数据一致性：不完整重写保留原数据；通过 SQLite 触发器注入尾帧写入错误，验证镜头和素材全部回滚；剧集接口的版本标识与返回镜头一致。
- 模型输入：参考图编号与图片顺序一致，文字模型和视频模型收到相同顺序；首尾帧描述正确；空提示词、重复 Agent 结果和未生成完整的参考图不会进入后续写入或模型调用。
- 完整测试保留数据库迁移、权限检查、素材历史、流式响应中断、PDF 导入及真实 FFmpeg 音视频合成的检查。

浏览器使用隔离的临时数据库和上传目录，在生产构建上检查：

- 人为阻塞保存请求，确认新输入不会被旧响应覆盖，生成请求在保存完成后才发出；模拟保存失败，确认生成停止，重新编辑后可恢复。
- 人为阻塞版本加载，确认版本标识与镜头一起切换；从旧版本预览返回分镜页后，两者保持一致。
- 卡片和抽屉中的提示词保存、切换镜头、上传、素材历史恢复、清空后重新创建，以及两个参考图字段独立保存。
- 320、390、768、1440 像素宽度下的页面和抽屉，嵌套预览关闭及键盘焦点。
- 一键生成固定使用刚创建的分镜版本，任一步失败即停止后续生成。
- 生产独立运行目录的数据库访问、上传文件读取、带用户标识的 ZIP 下载，以及已移除接口的拒绝行为。

## 验证边界

外部 AI 服务使用模拟响应验证请求格式、图片顺序、失败处理与数据写入，没有调用真实付费账号。视频合成使用本地 FFmpeg 和实际音视频文件验证。远程服务的账户权限、配额和实际生成质量仍需要用使用者自己的服务配置确认。

本轮没有改变部署方式或执行线上数据迁移。此前记录的使用范围仍有效：客户端用户标识用于当前私有工具的资源归属判断；生成任务依赖当前请求执行，不提供进程重启后的任务恢复。
