# 生成与导入流程优化（2026-09-28）

本轮沿用 Next.js、SQLite、Drizzle 和 Zustand，集中处理角色生成的重复逻辑、生成参数定义、导入页面职责，以及浏览器回归。只维护当前接口，没有增加旧参数转换或兼容入口。

## 改动

- 角色图片的单次、批量生成调用同一个业务函数，角色查询复用已有的剧集角色查询函数。批量通过 `p-map` 将并发限制为 3，跳过已有图片，保留每个角色的成功或失败结果。
- 生成入口按操作定义 Zod 参数，并从规则推导 TypeScript 类型。前端共用 `requestGeneration`，业务函数只接收对应操作的输入；资源归属检查单独放在服务端模块。图片比例包括界面已有的自适应选项，Agent 仍可在没有普通模型配置时执行。
- 导入页面从 1,011 行缩减为 104 行。流程状态、请求和重试集中在 `use-project-import.ts`；上传、步骤导航、角色确认、剧集确认和日志展示分别由组件负责。当前导入和历史记录复用确认组件，角色提取首次执行和重试共用函数。手机端将步骤导航放到正文上方。
- 导入最终创建先校验完整参数，再在一个 Drizzle 事务内写入角色、角色关系、剧集、剧集角色关联和完成日志。中途失败会回滚，避免重试时保留前一次的部分数据。相同剧集中的重复角色名称只建立一次关联。
- 增加 Playwright 测试与 CI 步骤。测试自动启动生产独立构建，使用临时数据库和上传目录，每个用例使用独立项目；失败时保存截图和执行记录。

## 验证

Vitest 共 69 项测试，覆盖原有功能并新增：

- 角色图片批量并发上限、单项失败后继续、已有图片跳过、单次与批量图片历史一致。
- 缺失必要字段、错误字段类型、无效比例或生成模式、空文本在生成前被拒绝，已有数据保持不变。
- 通过 SQLite 触发器制造第二个剧集写入失败，验证角色、关系、剧集和关联全部回滚；移除故障后重试只创建一份数据。无效导入参数在写入前被拒绝。

Playwright 共 6 项浏览器回归：

1. 延迟保存响应期间继续输入，旧响应保留新草稿；生成等待保存完成。
2. 保存失败阻止生成，重新编辑并保存后恢复生成。
3. 延迟加载分镜版本、从预览返回后，显示镜头和生成请求使用同一版本。
4. 上传新增素材版本，前后切换历史，刷新后仍保留选中的版本。
5. 导入角色提取和分集失败后从正确步骤重试，保留角色类型、剧集标题与删除结果，再通过真实接口创建数据；检查 390 和 1440 像素宽度。
6. 显示导入历史的最新成功结果，新建导入时清空前次流程状态。

运行方式见 README 的“开发与维护”。浏览器中的外部 AI 请求使用固定响应，保存、上传、文件解析和导入创建调用实际接口；没有调用真实付费 AI 账号。

本轮没有改动数据库结构，也不新增迁移。后台任务恢复和大体积 ZIP 流式下载仍按实际使用需求安排。
